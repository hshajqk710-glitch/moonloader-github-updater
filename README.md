# 🔄 MoonLoader GitHub Auto-Updater

Универсальный, надежный и отказоустойчивый шаблон системы автообновления для Lua-скриптов (SAMP / Arizona RP / MoonLoader / MonetLoader). 

Этот инструмент решает главные проблемы классических апдейтеров: не крашит игру при отсутствии интернета, корректно работает на мобильных клиентах и защищен от кэширования GitHub.

---

## 📌 Что внутри репозитория?
В репозитории подготовлены все необходимые файлы для работы апдейтера:
* **`version.txt`** — файл с версией на сервере (GitHub), по которому скрипт проверяет наличие обновлений.
* **`updater_template.lua`** — готовый пример скрипта-шаблона со встроенным автоапдейтером, который вы можете взять за основу для своего проекта.

---

## ⚙️ Принцип работы

1. **Тихая проверка при старте:** Спустя несколько секунд после запуска игры скрипт в фоновом потоке скачивает с GitHub файл `version.txt` и сверяет его с текущей локальной версией (`LOCAL_VERSION`).
2. **Многоуровневые сетевые транспорты:** Если у игрока на сборке не работает стандартная функция `downloadUrlToFile`, скрипт поочередно пробует другие методы: `requests`, `ssl.https` и `socket.http`.
3. **Безопасное уведомление:** При обнаружении новой версии скрипт не спамит в чат и не прерывает игру, а выводит аккуратное локальное диалоговое окно.
4. **Нативный перехват нажатий (`sampHasDialogRespond`):** Поскольку диалог локальный, ответы на него не уходят на сервер, что полностью защищает игрока от киков античита.
5. **Обход кэша GitHub:** Скрипт мгновенно скачивает новый `.lua` файл по прямой ссылке, даже если сервер GitHub (CDN) еще удерживает старую версию в кэше.
6. **Безопасная установка:** Скрипт делает бэкап старой версии (`.bak`), скачивает обновление во временный файл, заменяет его и автоматически перезагружает скрипт в памяти (`info:reload()`).

## 💻 Как подключить автообновление в свой скрипт?

### Шаг 1. Настройка переменных
Скопируйте код из файла `updater_template.lua` в свой проект и укажите данные вашего репозитория в блоке настроек:

```lua
local SCRIPT_FILENAME = 'YourScript.lua' -- Точное имя вашего скрипта на GitHub
local GH_USER, GH_REPO, GH_BRANCH = 'ВашНикGitHub', 'НазваниеРепозитория', 'main'


### Шаг 2. Добавление проверки в главный цикл (`main`)
В вашем бесконечном цикле `while true do` обязательно добавьте блок отслеживания нажатий на кнопки диалога обновления:

```lua
-- Ловим нажатия в локальном диалоге апдейтера
local result, button = sampHasDialogRespond(UPDATE_DIALOG_ID)
if result then
    pendingUpdatePrompt = false 
    promptedVersion = remoteVersion

    if button == 1 then
        updateAvailable = true
        doUpdate() -- Запускает скачивание и установку
    else
        sampAddChatMessage("[Updater] Обновление отложено. Введите /update для установки.", 0xFFAA00)
    end
end

###Шаг 3. Публикация релизов
Залейте в корень вашего репозитория файл version.txt (внутри него должна быть только строка с текущей версией, например: 1.0.0).

Залейте туда же актуальный файл вашего скрипта (например, YourScript.lua).

При выходе обновления: измените версию в .lua файле, сделайте коммит на GitHub, а затем обновите цифру в version.txt. Скрипт у пользователей автоматически обнаружит разницу и предложит обновление!
